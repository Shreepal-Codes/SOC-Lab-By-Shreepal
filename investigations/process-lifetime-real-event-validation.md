
# Process Lifetime Correlation — Real Windows Event Validation

## 1. Objective

Validate the process lifetime correlation module against actual Windows Security audit events.

The objective was to confirm that the module can:

- Parse real Windows Security Event ID 4688 (Process Creation).
- Parse real Windows Security Event ID 4689 (Process Termination).
- Normalize and correlate process identifiers.
- Match a process creation event with its corresponding termination event.
- Calculate the process lifetime.
- Report unmatched terminations and correlation anomalies.

## 2. Test Environment

| Component | Details |
|---|---|
| Operating System | Windows 11 |
| Event Log | Windows Security |
| Creation Event | 4688 |
| Termination Event | 4689 |
| Test Process | PING.EXE |
| Executable Path | C:\Windows\System32\PING.EXE |
| Analysis Module | analysis/process-ancestry-analysis.ps1 |

## 3. Test Procedure

A controlled PING process was launched using PowerShell:

```powershell
$testProcess = Start-Process `
    -FilePath "$env:WINDIR\System32\PING.EXE" `
    -ArgumentList @('-n', '11', '127.0.0.1') `
    -PassThru

$testProcess.WaitForExit()
```

The process was allowed to terminate naturally.

Windows Security events 4688 and 4689 were retrieved from the Security event log and passed through the custom lifecycle event parser.

The parsed events were then passed to:

```powershell
Invoke-ProcessLifetimeCorrelation -Events $matchingEvents
```

No unmatched termination events or correlation anomalies were reported for this test.

## 6. Validation Outcome

**Result: PASSED**

The real-world validation demonstrated that the process lifecycle parser and correlation logic can operate on actual Windows Security audit event XML, rather than relying exclusively on synthetic test fixtures.

The experiment successfully validated:

- Real Windows event XML parsing.
- Process ID normalization and matching.
- Creation-to-termination correlation.
- Process lifetime calculation.
- Basic unmatched-event and anomaly reporting.

## 7. Limitations

This was a controlled single-process validation.

The result does not establish that every possible process lifecycle scenario is handled correctly.

Additional validation is required for:

- PID reuse across multiple process instances.
- Duplicate process creation records.
- Missing creation or termination events.
- Out-of-order and delayed event delivery.
- Process name mismatches.
- High-volume event collection.
- Ambiguous process identifiers.

A successful correlation in this experiment should not be interpreted as proof that PID-only correlation is universally reliable.

## 8. Conclusion

The process lifetime correlation module successfully processed actual Windows Security events generated by a controlled PING process.

It correctly matched Event ID 4688 with Event ID 4689 and calculated the process lifetime with zero reported anomalies.

This provides practical evidence that the module works against real Windows audit data and establishes a foundation for further process ancestry and lifecycle investigation capabilities in the SOC Investigation Lab.
